# Changelog

Entries are grouped by release, newest first. Each entry is a summary written for people who fund and direct the work rather than a full commit list; see the git log for that.

## Unreleased

- Each finding now records which model first produced it. The model appears on the findings list and finding pages, in the JSONL findings exports and sharing bundles (surviving import into another instance), and the reporting page adds a per-model breakdown of scans, findings, and cost. Existing findings are attributed to their producing scan's model on upgrade.

## 2026-09-12

- Closed a proxy bypass that let a scan container access controls reserved for the operator. Hardened deployments using proxy sidecars now require an updated runner image; pull or rebuild it when updating the host binary. ([#1034](https://github.com/alpha-omega-security/scrutineer/pull/1034), [@p-linnane](https://github.com/p-linnane))
- Codex scans and chat sessions can now use a dedicated ChatGPT subscription login, with account-backed work running one at a time to prevent conflicting credential refreshes. ([#1017](https://github.com/alpha-omega-security/scrutineer/pull/1017), [@p-linnane](https://github.com/p-linnane))
- Codex's model list now includes GPT-5.6 and GPT-6 Astra. Cost reporting adds estimates for Astra and Daybreak Blue and corrects understated GPT-5.6 Sol costs. ([#1014](https://github.com/alpha-omega-security/scrutineer/pull/1014) [#1018](https://github.com/alpha-omega-security/scrutineer/pull/1018), [@p-linnane](https://github.com/p-linnane))
- The home page and repository list now load much faster on installations with large amounts of cached repository data. ([#1009](https://github.com/alpha-omega-security/scrutineer/pull/1009), [@p-linnane](https://github.com/p-linnane))
- Findings marked as not viable in production are now blocked before disclosure is sent to CERT/CC through VINCE. ([#1006](https://github.com/alpha-omega-security/scrutineer/pull/1006), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Repository findings exported as JSONL can now be limited to the Findings tab's results, leaving out separate scanner output. ([#1010](https://github.com/alpha-omega-security/scrutineer/pull/1010), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Saving a finding now retries while another operation holds the database lock, reducing failed analyst edits and scan updates; a lock that outlasts the retry window is reported as a temporary failure. ([#1022](https://github.com/alpha-omega-security/scrutineer/pull/1022), [@p-linnane](https://github.com/p-linnane))
- Fixed Codex scans falling back to reduced tool support because the runner image was missing the Code Mode helper. ([#1018](https://github.com/alpha-omega-security/scrutineer/pull/1018), [@p-linnane](https://github.com/p-linnane))
- Fixed the runner restart action doing nothing when the configured concurrency had not changed. ([#1017](https://github.com/alpha-omega-security/scrutineer/pull/1017), [@p-linnane](https://github.com/p-linnane))
- Fixed an authentication error when exporting findings from a sub-package's page. ([#1003](https://github.com/alpha-omega-security/scrutineer/pull/1003), [@be-student](https://github.com/be-student))
- CSAF advisory exports now report a database lookup failure instead of silently omitting information or claiming that an existing finding is missing. ([#1007](https://github.com/alpha-omega-security/scrutineer/pull/1007), [@alexandre-daubois](https://github.com/alexandre-daubois))

## 2026-09-08

- Native code bundled inside a project, whether pulled in as a git submodule or built as a compiled extension, is now mapped and audited alongside the main language, and a defect in a vendored component is attributed to its upstream source. ([#908](https://github.com/alpha-omega-security/scrutineer/pull/908) [#909](https://github.com/alpha-omega-security/scrutineer/pull/909), [@andrew](https://github.com/andrew))
- Every confirmed finding is now assessed for whether it can be reached in a released build, so a flaw that only exists in test or example code is marked as such rather than treated the same as one on a shipped path. ([#900](https://github.com/alpha-omega-security/scrutineer/pull/900), [@abhinavgautam01](https://github.com/abhinavgautam01))
- A finding's severity is now capped when verification shows a protection recorded in the project's threat model stopped the attack, or that exploiting it would need access as damaging as the flaw itself, and the evidence behind each cap is kept with the finding. ([#936](https://github.com/alpha-omega-security/scrutineer/pull/936) [#938](https://github.com/alpha-omega-security/scrutineer/pull/938) [#955](https://github.com/alpha-omega-security/scrutineer/pull/955), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Before a finding is marked as reported, connected peer instances are now asked whether one of them has already claimed it, so a maintainer is not contacted twice about the same issue. ([#913](https://github.com/alpha-omega-security/scrutineer/pull/913), [@alexandre-daubois](https://github.com/alexandre-daubois))
- The scans list can now be filtered by whether each run covered everything it was meant to, and that verdict is now checked against evidence the run returned rather than taken from the audit's own claim. ([#924](https://github.com/alpha-omega-security/scrutineer/pull/924) [#996](https://github.com/alpha-omega-security/scrutineer/pull/996), [@abhinavgautam01](https://github.com/abhinavgautam01))
- The usage page now shows how scan cost relates to a repository's size and audit workload, and flags individual runs that cost well above what is typical for their kind. ([#921](https://github.com/alpha-omega-security/scrutineer/pull/921), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Named audit steps can now be set to run directly on the operator's machine while everything else stays in a container. ([#985](https://github.com/alpha-omega-security/scrutineer/pull/985), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Python projects are now additionally checked with the Bandit analyser. ([#947](https://github.com/alpha-omega-security/scrutineer/pull/947), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Scala projects are now supported. ([#972](https://github.com/alpha-omega-security/scrutineer/pull/972), [@andrew](https://github.com/andrew))
- Hardened the scanner against a repository crafted to reach files outside its working area, run commands on the operator's machine during patch validation, or use the scan's credentials to alter findings from earlier runs. ([#961](https://github.com/alpha-omega-security/scrutineer/pull/961) [#974](https://github.com/alpha-omega-security/scrutineer/pull/974) [#993](https://github.com/alpha-omega-security/scrutineer/pull/993) [#994](https://github.com/alpha-omega-security/scrutineer/pull/994), [@p-linnane](https://github.com/p-linnane))
- Working directories left behind when a scan is interrupted by a restart are now cleaned up automatically. ([#942](https://github.com/alpha-omega-security/scrutineer/pull/942), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Fixed a case where a repository could be labelled unmaintained before all the checks that decide that had run. ([#889](https://github.com/alpha-omega-security/scrutineer/pull/889), [@mechko](https://github.com/mechko))
- Fixed the opencode backend failing to reach its configured provider when running under Podman on a machine with its own proxy set. ([#979](https://github.com/alpha-omega-security/scrutineer/pull/979), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Fixed a case where a finding was recorded again as new when a rescan reported it at a slightly shifted line range. ([#970](https://github.com/alpha-omega-security/scrutineer/pull/970), [@abhinavgautam01](https://github.com/abhinavgautam01))

## 2026-08-25

- A proposed patch is now re-attacked with generated variants of the original exploit before it is marked as holding, and any input that gets through is kept and replayed against the next attempt. ([#862](https://github.com/alpha-omega-security/scrutineer/pull/862), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Verifying a finding now records the full exploit path from public entry point to affected code, with evidence cited at each step, so a confirmed result shows how the attack reaches its target and a rejected one shows what stops it. ([#851](https://github.com/alpha-omega-security/scrutineer/pull/851), [@abhinavgautam01](https://github.com/abhinavgautam01))
- A repository's commit history is now searched for past security fixes that were never publicly announced, and what turns up feeds into its threat model and the advisory audit. ([#848](https://github.com/alpha-omega-security/scrutineer/pull/848), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Every scan now records whether it covered the whole repository or stopped part-way, so a result with no findings can be told apart from a run that did not finish. ([#828](https://github.com/alpha-omega-security/scrutineer/pull/828), [@charlie-morrison](https://github.com/charlie-morrison))
- Each dependency recorded for a repository is now flagged for supply-chain risks such as a single maintainer, an expired contact domain, no published security policy, or no release in over eighteen months. ([#871](https://github.com/alpha-omega-security/scrutineer/pull/871), [@abhinavgautam01](https://github.com/abhinavgautam01))
- The security audit now checks for library interfaces whose defaults are unsafe or whose failures are silent, and reports a dangerous pattern repeated across a codebase as one systemic finding instead of many separate ones. ([#878](https://github.com/alpha-omega-security/scrutineer/pull/878), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Findings in a project's GitHub Actions workflows now carry a cited explanation of the attack technique they expose. ([#847](https://github.com/alpha-omega-security/scrutineer/pull/847), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Scans can now be driven by GitHub Copilot alongside the existing Claude, Codex and opencode options. ([#874](https://github.com/alpha-omega-security/scrutineer/pull/874) [#881](https://github.com/alpha-omega-security/scrutineer/pull/881), [@scovetta](https://github.com/scovetta))
- The opencode backend can now be pointed at any provider the operator configures, including a model running on the operator's own machine. ([#883](https://github.com/alpha-omega-security/scrutineer/pull/883) [#894](https://github.com/alpha-omega-security/scrutineer/pull/894) [#896](https://github.com/alpha-omega-security/scrutineer/pull/896), [@andrew](https://github.com/andrew))
- OCaml projects are now supported. ([#901](https://github.com/alpha-omega-security/scrutineer/pull/901), [@andrew](https://github.com/andrew))
- A `default_model` pinned in the config file but missing from the model pick list is now reported at startup instead of being silently ignored, and the documentation and sample configuration now use current-generation model ids. ([#816](https://github.com/alpha-omega-security/scrutineer/pull/816), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Importing results from another scanner now caps how many findings any one rule can contribute, so a single over-broad check cannot flood the review queue or run up verification costs. ([#867](https://github.com/alpha-omega-security/scrutineer/pull/867), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Scheduled scans across many repositories now run several at once, and a repository that is slow to reach no longer holds up the rest. ([#853](https://github.com/alpha-omega-security/scrutineer/pull/853), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Fixed a case where a C or C++ project that ships Perl test scripts was audited with the Perl toolchain instead of the native one. ([#885](https://github.com/alpha-omega-security/scrutineer/pull/885), [@mechko](https://github.com/mechko))
- Fixed a case where the same reference could be attached to a finding more than once; existing duplicates are merged on upgrade. ([#865](https://github.com/alpha-omega-security/scrutineer/pull/865) [#869](https://github.com/alpha-omega-security/scrutineer/pull/869), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Fixed a case where focus-area audits launched automatically after a threat-model run used a weaker AI model than the one configured for them. ([#880](https://github.com/alpha-omega-security/scrutineer/pull/880), [@mechko](https://github.com/mechko))

## 2026-08-11

- Monorepos can now be scanned one sub-package at a time, with each package getting its own findings, advisories and disclosure route instead of everything rolling up into one entry. ([#806](https://github.com/alpha-omega-security/scrutineer/pull/806), [@dkw-oss](https://github.com/dkw-oss))
- Scanning a repository now records the list of components it depends on, giving licence and known-vulnerability checks a single inventory to work from. ([#801](https://github.com/alpha-omega-security/scrutineer/pull/801), [@andrew](https://github.com/andrew))
- Finding pages now show a migration guide for abandoned or zombie packages, combining repository health, published packages, alternatives, and dependent exposure status. ([#762](https://github.com/alpha-omega-security/scrutineer/pull/762), [@abhinavgautam01](https://github.com/abhinavgautam01))
- For a finding in an abandoned package, operators can now record where each affected downstream project stands on migrating away from it. ([#808](https://github.com/alpha-omega-security/scrutineer/pull/808), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Confirming a finding now runs its reproduction three times and grades the result against a fixed checklist, so a pass carries repeatable evidence. ([#831](https://github.com/alpha-omega-security/scrutineer/pull/831), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Every scan now keeps a copy of the settings it ran with and a link to the run it was retried from, so past results can be reproduced and compared. ([#823](https://github.com/alpha-omega-security/scrutineer/pull/823), [@charlie-morrison](https://github.com/charlie-morrison))
- A repository whose maintainer asks not to be scanned can now be marked as such, stopping any work under way and blocking all future runs against it. ([#753](https://github.com/alpha-omega-security/scrutineer/pull/753), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Operators on a restricted network can now turn off the third-party data fetched from ecosyste.ms, and a scan that cannot reach that service moves on immediately. ([#790](https://github.com/alpha-omega-security/scrutineer/pull/790), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Instances can now publish opt-out requests, confirmed disclosure routes and fix-audit results to a shared feed and pull in peers' feeds automatically, with negative fix-audits going to an encrypted members-only channel. ([#752](https://github.com/alpha-omega-security/scrutineer/pull/752) [#778](https://github.com/alpha-omega-security/scrutineer/pull/778), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Encrypted imports and the members-only feed can now be opened with a key held on a hardware token or in an external secret store. ([#818](https://github.com/alpha-omega-security/scrutineer/pull/818), [@p-linnane](https://github.com/p-linnane))
- Reviewed findings can now be filed directly with CERT/CC through its VINCE coordination service, from the same page the analyst approved them on. ([#776](https://github.com/alpha-omega-security/scrutineer/pull/776), [@andrew](https://github.com/andrew))
- Four focused audits can now be run on demand alongside the general scan, covering data exfiltration, authorisation boundaries, personal-data exposure, and memory safety in native code. ([#777](https://github.com/alpha-omega-security/scrutineer/pull/777) [#784](https://github.com/alpha-omega-security/scrutineer/pull/784) [#809](https://github.com/alpha-omega-security/scrutineer/pull/809) [#822](https://github.com/alpha-omega-security/scrutineer/pull/822), [@abhinavgautam01](https://github.com/abhinavgautam01))
- Re-checking an open finding now skips the AI call when the affected file has not changed since the finding was raised. ([#785](https://github.com/alpha-omega-security/scrutineer/pull/785), [@abhinavgautam01](https://github.com/abhinavgautam01))
- The scans list, repositories list and per-repository Scans tab now update live as scans start, finish or change state, without disturbing the reader's place, filters or sort. ([#813](https://github.com/alpha-omega-security/scrutineer/pull/813), [@alexandre-daubois](https://github.com/alexandre-daubois))
- Fixed a case where the access token for a private skills repository could appear in logs and process listings; it is now kept off the command line and URLs that embed one are rejected. ([#814](https://github.com/alpha-omega-security/scrutineer/pull/814), [@abhinavgautam01](https://github.com/abhinavgautam01))
